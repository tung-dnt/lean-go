# Routes, paths and guards

How a route is registered, linked to and guarded. Read `internal/server/routes.go` (every route) once before you start.

- **Adding a domain's routes.** In `addRoutes` (`internal/server/routes.go`), under a comment line naming the domain, make the handlers from the fields of `d` and register them: `mux.Handle("GET /notes/{id}", note.HandleShow(d.queries))`, read with `r.PathValue("id")`. `GET` also serves `HEAD`. **Register the home page as `GET /{$}`**: a bare `GET /` is a subtree pattern that takes every GET no other route has, so the 404 page of the catch-all (`mux.Handle("/", HandleNotFound())`) would never be drawn for a GET. A maker only keeps what it is given: `internal/server/paths_test.go` makes the routes from dependencies that are nil, so what is read from one is read when a request is served, not when the handler is made. A new dependency (a client of a third-party service, say) is built in `Run`, passed to `NewServer` and kept in `deps`.
- **Paths.** Never spell a path in a link, a form action or a redirect: `paths.Note(id)`, `paths.Home` (`internal/server/paths`). A new route adds its path there and a row to `routes` in `internal/server/paths_test.go` (and to the wildcard table when it has a `{wildcard}`); the test fails for a path that leads nowhere.
- **Guards and middleware placement.** The middleware every page goes through are in `NewServer`, outermost first, each with the reason for its place; files and `/healthz` skip them (`isBare`). Per-route middleware is applied in `routes.go`: `requireAuth`/`requireNoAuth` (`middleware.RequireAuth(fail)`), `middleware.CacheControl`, `middleware.GzipFiles`, and, on a route that takes a large body, `middleware.LargeBody(limit, timeout, layouts.Error)(handler)`: it caps the body, moves the read/write deadlines and the request's own deadline for that route only. Everything at or below `/admin` is held to the admin check by `NewServer`, a route nobody wrote yet included, so an admin route needs no wrapper (`POST /admin/notes/{id}/delete`). A get never changes anything: an action is a post. Do not register a page pattern that ends in `/` (the router redirects `/x` to `/x/` and `RemoveTrailingSlash` back).
